# V1.1.1 release notes

## Document overview

This document records the V1.1.1 host UI cache-consistency fix, its regression
coverage, and the ARM64 deployment verification. V1.1.1 retains the host-side
experiment grouping introduced in V1.1.0; the earlier single-capture
acceptance and immutable V1.1.0 source/image identity remain in the
[V1.1.0 release notes](v1.1.0-release-notes.md).

## Scope and current status

V1.1.1 fixes mixed-generation browser assets that could leave HTML controls
paired with an older cached JavaScript file. During `create_api`, the service
reads the three packaged web assets as a process-startup snapshot. The HTML
references JavaScript and CSS by full SHA-256 query URLs, and the HTML, JavaScript,
and CSS responses all send `Cache-Control: no-cache`. The unhashed asset routes
remain valid. The URL hash and served bytes therefore stay consistent for that
API process; updating packaged assets takes a rebuilt image and API restart.

The static translation regression harness now builds text and ARIA nodes from
the actual `index.html`, checks that every referenced key has non-key Chinese
and English translations, and verifies both language renders. It includes the
reported `group.manage` and `history.filter.mode` labels. No translation fallback
or new dependency was introduced.

The V1.1.1 ARM64 image was built from candidate source revision
`7ab2b19c460b8f6f11ab504cf0ee7fd56d222ad5` and deployed for UI/cache verification.
Its identity is `tuss4470-acquisition-core:1.1.1`, image ID
`sha256:acbc213fd0ae3ded2e15196995567e544f576d99efc3516d1a80fd804b2d1a7d`,
with OCI revision matching that candidate. Core and Bridge both ran this image
during verification and are currently running it. The services were stopped
before the persistence backup, then brought up again on this image. The V1.1.0
tag and image remain unchanged. The later documentation-closeout commit is
separate from the image's candidate source identity.

The Windows host suite passed 261 tests in 19.34 s; the Jetson ARM64 suite passed
259 tests with 2 Windows-only skips in 28.29 s. Node web tests and shell syntax
checks passed on both platforms. The initial Jetson test temporary-parent setup
issue was corrected without source changes and was not a product failure.

On the deployed API, all three HTML/JavaScript/CSS responses returned
`Cache-Control: no-cache`. The JavaScript URL hash
`2f84c887414b97d7964e3bb838aa7b88cd285b8bf0e36fd3d07e6a724b5a1e13` and CSS URL
hash `b2c6a179ee43237c63181e4a4713b51825fcded7decddfde1792e5c713977864` matched
the corresponding response bytes. A fresh Jetson page in the in-app browser
rendered both Chinese and English without raw translation keys or console
warnings/errors; `group.manage` displayed “管理实验与分组” / “Manage experiments
and groups”, and `history.filter.mode` displayed “筛选方式” / “Filter by”. The
previous mixed-generation behavior was reproduced with old JavaScript paired
with new HTML. The user's pre-existing native-browser cache was not directly
inspected; if stale page state remains, one hard refresh (`Ctrl+Shift+R`) may be
needed.
