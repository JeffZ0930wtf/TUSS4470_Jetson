# V1.0.0 firmware verification migration

## Document overview

This document maps every pre-V1 firmware build or verification script to the
hardware or protocol behavior it protects and to its V1 disposition. It
prevents file renaming and removal from silently weakening the accepted safety
gate. It applies to Tasks 5–7 of the V1 release consolidation plan and is the
review checklist for the final `scripts/test-all.ps1` firmware section. The V1
baseline document remains the loadable-image comparison authority; this file
defines test ownership rather than new firmware behavior.

## Migration rule

A production invariant remains in the aggregate gate under a responsibility-
based name. A diagnostic-only image may leave the active tree only when its
production-relevant invariant is covered elsewhere or the assertion describes
the retired diagnostic mechanism itself. No diagnostic-only software trigger,
single-word DMA path, or reduced-RAM stub is added to production firmware merely
to preserve an obsolete test.

## Required V1 gate coverage

The final aggregate gate is complete only when the following ownership is
visible in named scripts or tests:

- Clock: XT2 pin setup, DCORSEL 6, 24 MHz FLL configuration, and runtime fault
  shutdown.
- TUSS4470: SPI divider/vector/parity, ordered register write/readback,
  Standby/VDRV Hi-Z startup, VDRV readiness, and unsafe-profile rejection.
- Reset/session: IO2 and NCS safe latches, stopped Burst/ADC timers, DTR low to
  rising-edge requirement, new-session invalidation, and safe closure.
- Acquisition: 2048 real `uint16` samples in one 4096-byte buffer, configurable
  sample ticks, pretrigger accounting, exact DMA completion, raw ordering, no
  interpolation/synthesis, and bounded memory.
- Transport: stable segmented CAPTURE_DATA bytes, CRC/framing/resynchronization,
  CDC busy non-advancement, TX completion ownership, and USB DMA exclusion.
- Control: IO_MODE mapping, finite 1–63 Pulse plans, periodic count, STOP,
  lease renewal/expiry, Slave/Master synchronization, event encoding, and
  no automatic capture retry.
- Timer ownership: TA1 initialization after TI USB setup remains an explicit,
  independently named regression check.

The host Bridge tests separately own serial/TCP closure, durable spool replay,
SQLite commit confirmation, reconnect behavior, and DTR fail-safe handling;
those are not duplicated in firmware-only scripts.
