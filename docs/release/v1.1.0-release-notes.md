# V1.1.0 release notes

## Document overview

This document records the V1.1.0 source change, its verification evidence, and
the boundary between source synchronization and runtime-image deployment. It
supplements the [V1.0.0 acceptance record](v1.0.0-acceptance.md), which remains
the baseline for physical acquisition evidence, and the
[V1.0.1 release notes](v1.0.1-release-notes.md), which describe the currently
selected Jetson runtime image.

## Release scope

V1.1.0 packages the host-side experiment data grouping work. The source package
and future image-build identity are `1.1.0`. This source change does not change
the currently selected runtime image: Compose and the Jetson startup script
continue to default to `tuss4470-acquisition-core:1.0.1`. No 1.1.0 image build,
container switch, or real-device acquisition check is claimed here.

The release adds experiment and group metadata in the existing Core SQLite
database, freezes the selected group when a task starts, supports independent
history filtering and batch assignment, and exports a group's archived data as
a ZIP. Existing captures remain ungrouped unless assigned. The feature does
not copy or transform waveform data.

Firmware remains `0.2.0.2`, wire protocol remains v1, and raw samples,
acquisition behavior, and third-party dependency resolutions are unchanged.
The local project version in `uv.lock` follows the package version; no third-
party package was upgraded for this release.

## Verification evidence

The final functional candidate `827438a` (see the
[implementation record](../superpowers/plans/2026-10-09-experiment-data-grouping.md))
passed the Windows aggregate gate on 2026-10-12: 259 Python tests passed in
17.70 seconds; Node Web regressions, production firmware compilation, MCU
simulator, official TI USB build, and retained safety/timing/ADC/lease checks
also passed. Firmware text/data/bss remained `26886/98/6118`. No firmware was
flashed and no Burst was requested. The source-version-only changes passed the
29 targeted project-layout and launcher checks in 2.67 seconds, plus
`bash -n scripts/test-all.sh`, Markdown local-link validation, and
`git diff --check`. The Linux Docker build script itself was not run.

An isolated simulator used explicitly synthetic records and no Bridge or
production database. Basic browser checks covered grouping controls, history
filters, empty-target refresh, ZIP entry point, batch-selection isolation, and
language switching on the earlier `5ee6a7b` candidate. The later save-context
race fix at `827438a` passed Node tests, but a browser refresh/manual acceptance
of that latest UI candidate remains pending. These checks do not establish
real-device or production-database acceptance.

## Deployment boundary

At the time these notes were prepared on 2026-10-13, merge/tag/push and Jetson
repository plus virtual-environment synchronization were coordinator follow-up
steps; this document does not claim their completion. Source or virtual-
environment synchronization is not an image deployment. The running/default
Core image remains `1.0.1` until a separately built and validated `1.1.0`
image is explicitly selected. Do not upgrade a production database as part of
source synchronization; back up the Core and Bridge persistent data directories
together and follow the deployment guide before any future runtime migration.

See the [Jetson deployment guide](../deployment/jetson.md) for the current
source/image distinction and the [experiment grouping design](../superpowers/specs/2026-10-09-experiment-data-grouping-design.md)
for the host-side contract.
