# V1.1.0 release notes

## Document overview

This document records the V1.1.0 source change, its verification evidence, and
the boundary between the immutable source tag, its validated Jetson image, and
later runtime-default maintenance. It
supplements the [V1.0.0 acceptance record](v1.0.0-acceptance.md), which remains
the baseline for physical acquisition evidence, and the
[V1.0.1 release notes](v1.0.1-release-notes.md), which describe the previous
launcher/image release.

## Release scope

V1.1.0 packages the host-side experiment data grouping work. The immutable
annotated source tag `v1.1.0` resolves to
`7db75e05875848fd02d188ba5196c2c1e06b5f5b`. The Jetson ARM64 image
`tuss4470-acquisition-core:1.1.0`, image ID
`sha256:c4eef7032a72d5e359b77bea2afc9507166b4e853506957beab7e350a269abf3`,
was built from that exact tagged source revision and is the image verified on
both current Core and Bridge containers. The follow-on runtime-default
maintenance changes Compose/startup defaults to select this existing image;
they do not alter or rebuild the tagged source/image.

The release adds experiment and group metadata in the existing Core SQLite
database, freezes the selected group when a task starts, supports independent
history filtering and batch assignment, and exports a group's archived data as
a ZIP. Existing captures remain ungrouped unless assigned. The feature does
not copy or transform waveform data.

Firmware remains `0.2.0.2`, wire protocol remains v1, and raw samples,
acquisition behavior, and third-party dependency resolutions are unchanged.
The local project version in `uv.lock` follows the package version; no third-
party package was upgraded for this release.

## Verification evidence

The final functional candidate `827438a` (see the
[implementation record](../superpowers/plans/2026-10-09-experiment-data-grouping.md))
passed the Windows aggregate gate on 2026-10-12: 259 Python tests passed in
17.70 seconds; Node Web regressions, production firmware compilation, MCU
simulator, official TI USB build, and retained safety/timing/ADC/lease checks
also passed. Firmware text/data/bss remained `26886/98/6118`. No firmware was
flashed and no Burst was requested. The source-version-only changes passed the
29 targeted project-layout and launcher checks in 2.67 seconds, plus
`bash -n scripts/test-all.sh`, Markdown local-link validation, and
`git diff --check`. The Linux Docker build script itself was not run.

After the version closeout was fast-forwarded into `main`, the exact candidate
`7d10b377b20fd8abf47db7b552c21fb9e5224aaa` passed the complete Windows gate on
2026-10-13: 259 Python tests in 17.67 seconds, Node regressions, production
firmware compilation, MCU simulator, official TI USB build, and all retained
static checks. The main checkout's locked editable installation reports
`1.1.0`; all four public commands passed `--help`. Firmware memory sizes remain
unchanged.

On the same candidate, the synchronized Jetson repository environment
(Python 3.12.3, Node v18.19.1) passed 257 Python tests in 28.18 seconds; the two
Windows-only launcher tests were correctly skipped. Node Web regression
passed. These are host tests using isolated test data, not a container build
or physical-device acceptance. The final release documentation adds no
non-documentation changes after this verified candidate.

An isolated simulator used explicitly synthetic records and no Bridge or
production database. Basic browser checks covered grouping controls, history
filters, empty-target refresh, ZIP entry point, batch-selection isolation, and
language switching on the earlier `5ee6a7b` candidate. The later save-context
race fix at `827438a` passed Node tests, but a browser refresh/manual acceptance
of that latest UI candidate remains pending. These checks do not establish
real-device or production-database acceptance.

## Jetson deployment and bounded physical evidence

On 2026-10-13, the Jetson was updated from the retained 1.0.1 image to the
ARM64 image above only after backing up the Core and Bridge persistent data
directories together. Both containers were confirmed running the 1.1.0 image.
The additive SQLite migration preserved all seven original archived records
and their frame/sample bytes. A single explicitly authorized Pulse=1
`SAVE_ALL` capture was bound to a verification group and completed; the archive
now contains eight records (one grouped, seven ungrouped), with Bridge pending
count zero and device state `NORMAL / IDLE`.

The new capture's 2048 decoded samples matched its SQLite BLOB and 4096-byte
download exactly. Group filtering selected only the new capture and the
ungrouped filter returned the previous seven. Its group ZIP contained the
`.usac`, `.u16le`, `.json`, and manifest; binary members matched stored bytes.
SQLite integrity check was `ok`. Timing remains `TIMING_UNCALIBRATED`; this
evidence covers one real single capture, grouping/filtering/ZIP, not periodic
or sweep hardware coverage, manual browser acceptance, calibrated timing, or
long-term reliability. No firmware was flashed.

The post-tag runtime-default maintenance changes only the three deployment/
startup files, their corresponding tests, and current documentation. It keeps source tag
`v1.1.0` at `7db75e0…` and the already validated image revision unchanged; it
does not rebuild, retag, or restart containers. Future database upgrades must
still stop Core/Bridge and back up both persistent data directories together.

The complete machine-generated evidence is stored outside the repository at
`D:/Desktop/TUSS4470_data/release/v1.1.0/jetson-20261013/`; the repository copy
of its deployment and verification summary is this release record and the
Jetson deployment guide. Do not treat the external evidence directory as
application data or commit its binary artifacts.

See the [Jetson deployment guide](../deployment/jetson.md) for the current
source/image distinction and the [experiment grouping design](../superpowers/specs/2026-10-09-experiment-data-grouping-design.md)
