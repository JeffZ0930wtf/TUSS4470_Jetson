# V1.1.3 删除补丁

## 文档说明

本文说明采集控制台如何删除实验、分组和已保存记录，记录相应的主机接口、数据边界和
部署注意事项。网页操作见 [中文 README](../../README.zh-CN.md)，REST 细节见
[协议文档](../protocol.md)，平台操作见 [Jetson 部署指南](../deployment/jetson.md)。

## 删除范围

| 操作入口 | 删除内容 |
| --- | --- |
| 编辑实验 | 该实验、其全部分组和这些分组中当前保存的波形 |
| 编辑分组 | 该分组和其中当前保存的波形 |
| 编辑历史记录 | 所选的一条已保存波形 |

确认弹窗会说明级联范围，并提示删除后无法在应用中恢复。数据库以一次事务完成删除。
归档中的波形样本、完整帧和事件行一并移除。其他实验、分组和未分组记录保留，运行
会话仍用于追溯当时的采集结果。已下载的文件和外部备份独立于数据库。SQLite 释放的
页可供后续写入复用，数据库文件未必立即缩小。

CLI 提供 `experiment-delete`、`group-delete`、`capture-delete`，均要求 `--yes`。
REST 的三个 `DELETE` 入口均要求 `confirm=true`。正在运行的相关任务须先结束。
Core 保留最小的已删帧身份校验记录，防止 Bridge 重放恢复波形。REST 仍为 v1，
线协议、固件和原始采样流程沿用 V1.1.2。

## 验证

- Windows 完整门禁通过，覆盖 273 项 Python 测试、网页回归、固件编译及静态安全检查。
- 浏览器检查了三种删除范围和取消操作。模拟库副本分别删除实验的两条记录、分组的一条
  记录和一条独立记录，两条对照记录的原始样本逐字节一致。强制事务失败后，六条记录均保留。
- 已删帧仍可确认 Bridge 重放，且旧帧不会重新出现在历史里。验证使用模拟器和临时库。

## 部署

这是主机与 SQLite 的变更。部署时在采集空闲、Bridge 待交付清空后停止服务，备份正式
数据目录，再按平台指南启动。本补丁使用临时数据库验证删除，现场数据不参与验证。
