# TUSS4470 波形分析工作台前端增量设计

## 文档说明

本文档定义 TUSS4470 超声采集子模块的波形展示与历史叠加前端增量，解决现有页面只能查看整条最近波形、无法选择连续原始窗口、无法批量叠加比较，以及 SQLite 数据保存位置不直观的问题。本文档适用于已经完成 M6 验证后的主机端 Web/API 维护增量，不属于新的采集里程碑，也不改变固件、硬件控制、串行协议、采集事务或 SQLite 持久化语义。

本文档是该增量的实现依据；总体模块边界、硬件安全门禁和里程碑流程仍以受控路线图、`CONTRIBUTING.md`、`docs/protocol.md` 及现有 M3—M6 设计与验收文档为准。当前状态为“已审查，可进入实施计划”；实现仍需按精简计划和 TDD 逐项验收。

## 1. 目标

本增量需要实现以下能力：

1. 用户可以指定连续原始采样窗口的起点和点数；
2. 原始 ADC 值与整帧独立归一化值可以切换显示；
3. 最多同时叠加 20 条相容波形；
4. 波形图成为页面中央的主要视觉区域，并在不同窗口宽度下保持可读；
5. 页面明确显示 SQLite 数据库的实际保存路径；
6. 新增内容完整支持中文和英文切换；
7. 保持原始采样值、数据库内容和下载文件完全不变。

本增量优先复用现有浏览器、REST API 和 SQLite 能力，不引入前端框架、批量波形接口或新的存储服务。

## 2. 已确认决策

| 项目 | 决策 |
|---|---|
| 页面结构 | 采用纵向主工作区：采集控制在上，波形居中，历史与存储信息在下，完整参数库继续向下排列 |
| 窗口含义 | 显示一段连续原始样本，不抽点、不降采样、不插值 |
| 显示模式 | 原始 ADC / 归一化 0–1 可切换 |
| 归一化范围 | 每条波形按其完整 2048 点独立计算最小值和最大值，然后截取所选窗口显示 |
| 叠加上限 | 同一画布最多显示 20 条波形，当前/最近波形也计入上限 |
| 波形加载 | 方案 1：继续逐条调用现有样本接口，浏览器按需加载并缓存，不增加批量样本 API |
| 数据库位置 | 仅在页面显示和复制路径，不允许修改、迁移、浏览目录或切换数据库 |
| 数据持久化 | 不修改 SQLite 表结构、原始 BLOB、保存策略或提交闭环 |

├──────────────────────────────────────────────────────────┤

│ [已选择 n/20] [清除叠加]                                 │

## 5. 连续原始窗口

### 5.1 控件

波形工具栏提供：

- `窗口起点`：整数，范围为 `0..sample_count-1`；
- `显示点数`：整数，范围为 `1..sample_count-窗口起点`；
- `上一窗口`：起点向前移动一个当前窗口宽度，并在 0 处截断；
- `下一窗口`：起点向后移动一个当前窗口宽度，并在末尾截断；
- `显示全部`：恢复 `窗口起点=0`、`显示点数=sample_count`。

输入既允许键盘精确填写，也可以使用浏览器原生步进控件。任何修改均只重绘浏览器内已有数据，不重新采集、不写数据库、不重新下载已缓存波形。

### 5.2 边界规则

- 非整数、空值或超出范围的输入不进入绘图状态；
- 页面显示清晰的范围提示，并保留上一次有效窗口；
- 切换到不同 `sample_count` 的新波形组时，窗口自动限制在新范围内；
- 当前第一版采集通常为 2048 点，但实现不得把 2048 写成只能支持这一长度的绘图假设；
- 绘图循环必须逐个使用所选窗口内的真实样本，不允许为了匹配画布像素而抽点或生成新样本；
- 横轴表示原始样本序号，不宣称为已经校准或对齐的物理时间；
- 合法的单点窗口必须在画布水平方向中央绘制一个明确的点，不得执行 `样本数-1` 为分母的坐标计算。

## 6. 原始与归一化显示

### 6.1 原始 ADC 模式

原始模式直接绘制解码后的无符号 16 位样本值，纵轴单位标为 `ADC counts` 并显示实际刻度。同时显示的所有波形共用同一纵轴变换，以保留波形之间的真实幅值关系。

为了让波形位于图形主体中央，纵轴按当前窗口中所有可见原始值的联合最小值和最大值自动取界，并在上下增加一致的视觉留白。该变换只决定屏幕坐标，不改变样本值；图例和提示中仍显示真实 ADC 数值。若所有可见值相同，则围绕该值使用一个最小非零显示范围，避免除零和贴边。

### 6.2 归一化模式

每条波形独立使用其完整帧计算：

```text
normalized[i] = (sample[i] - frame_min) / (frame_max - frame_min)
```

随后从该归一化结果中截取当前连续窗口绘图。改变窗口不得重新计算 `frame_min` 和 `frame_max`，从而保证同一条波形在不同窗口中的幅值基准不变。归一化模式的纵轴范围固定为 `0..1`，不得根据当前窗口再次自动缩放。

当 `frame_max == frame_min` 时，该波形的全部归一化值定义为 `0`，页面显示“恒定波形，归一化结果为 0”的提示。归一化值只存在于浏览器内存中，不写入 SQLite，不改变原始下载，不作为后续 BMS 数据接口的替代品。

## 7. 波形叠加

### 7.1 选择方式

- 最近一次波形默认作为当前波形显示；
- 每条 SQLite 历史记录提供叠加选择框；
- 页面具有简单的 `followLatest` 状态，初始值为 `true`；
- “查看”操作将目标历史波形设为唯一当前波形、清除原叠加组并把 `followLatest` 设为 `false`；
- 人工添加历史叠加时同样把 `followLatest` 设为 `false`，防止分析中的画面被下一帧替换；
- 页面提供明确的“恢复跟随最新”入口；恢复时以已知的最新 capture ID 重建唯一当前波形，并重新令 `followLatest=true`；
- 暂停跟随仅影响页面画面，采集、设备租约、SQLite 保存、会话轮询和历史刷新继续正常运行；
- “清除叠加”保留当前主波形，只移除额外历史曲线；
- 图例显示颜色、短 capture ID、序号和显示/隐藏控制；
- 颜色不是唯一识别信息，短 ID 必须始终可见。

本版明确采用静态叠加分析：人工查看或添加历史曲线后，当前波形组保持不变；不支持让实时最新曲线持续替换其中一条并与历史参考曲线动态叠加。界面必须用“已暂停跟随，采集仍在运行”和“恢复跟随最新”等明确文案区分画面状态与采集状态。

上限按不同 capture ID 计算。当前主波形、可见或隐藏的已选曲线，以及仍在加载中的已选记录，合计最多 20 条。同一 ID 只计一次；隐藏曲线不释放名额，只有从叠加组移除才释放名额。选择开始时先预留名额，加载失败或取消选择时释放。达到上限后，其他未选项保持可见但不可继续勾选，并显示“最多选择 20 条”。这一定义同时限制选择数、并发中的预留项和浏览器缓存规模，不需要额外缓存淘汰机制。

### 7.2 相容性规则

只有以下三项完全一致的波形才允许进入同一叠加组：

1. `sample_interval_ticks`；
2. `pretrigger_count`；
3. `sample_count`。

第一条波形建立叠加组的时间基准。参数不相容的历史项不可勾选，并明确列出不一致字段，而不是只显示笼统错误。其他设备参数、Burst 数、滤波器或增益差异不禁止叠加，因为比较这些变化本身就是实验用途。

改变设备配置不会清除已经加载的历史叠加组，也不会让绘图模块依赖配置编辑状态。只有实际选择或加载某一帧时，才根据该帧自己的元数据判断相容性。

当 `followLatest=true` 且新到达的最近波形与当前组不相容时，新波形成为唯一当前波形，旧叠加选择被清除，并显示一次非阻塞提示，避免在不同时间基准上绘制貌似可比较的曲线。当 `followLatest=false` 时，新帧只更新“有新波形”状态和历史记录，不覆盖当前人工查看的历史波形。

### 7.3 保存策略与临时波形

- `不保存` 产生的最近波形仍可立即显示，但标记为“临时/未保存”；
- 临时波形被下一条临时数据替换或页面刷新后，不承诺仍可加载；
- 历史叠加只以 SQLite 中可查询的持久化记录为稳定来源；
- `保存每一次` 和 `保存最后一次` 继续沿用现有后端语义，本增量不得改变其入库时机；
- `保存最后一次` 运行中返回的最近帧可以标记为滚动记录；会话进入终态后，页面使用同一个 capture ID 重新读取单帧元数据并刷新历史，将缓存中的保存状态更新为已归档，不重新下载未变化的原始样本；
- 页面不得把“已显示”表述为“已保存”。

## 8. 绘图与浏览器状态

继续使用原生 Canvas 2D，不增加图表依赖。画布占据内容区的主要宽度，CSS 控制视觉尺寸，JavaScript 按设备像素比同步实际画布尺寸；窗口缩放时只从缓存重绘。

浏览器保存以下页面状态：

```text
waveforms: Map<capture_id, {
  metadata,
  samples: Uint16Array,
  normalized: Float32Array | null,
  color,
  visible
}>

primaryCaptureId
windowStart
windowCount
displayMode
followLatest
latestCaptureId
viewRevision
```

20 条、每条 2048 个 `uint16` 原始点约占 80 KiB；即使包含归一化数组和元数据，内存规模仍很小，因此不需要服务器端合并或分块协议。Map 中只保留当前主波形和仍属于叠加组的记录；移除波形时同时删除其浏览器缓存，同一 capture ID 再次选择时才重新加载。

`viewRevision` 是一个简单递增整数。查看另一条主波形、清除叠加、恢复跟随最新或因不相容帧重建波形组时递增。每个异步元数据/样本请求记录发起时的 revision，并具有只属于该次请求的加载标识和名额预留。

请求成功、失败及 `finally` 收尾均必须先确认 revision、capture ID 和加载标识仍属于当前查看状态。旧请求可以自然结束，但其成功结果不得进入 Map 和画布，其失败不得显示为当前视图错误、删除新视图中的同 ID 记录，或释放后来请求重新取得的名额。不需要为此引入通用请求管理框架。

Canvas 会用折线连接相邻真实样本，这是绘图表现，不是产生插值采样值。实现不得在状态、接口或导出数据中创建伪造的中间点。

## 9. 数据流与接口

### 9.1 历史波形数据流

```text
SQLite 历史摘要
    │ GET /api/v1/captures
    ▼
浏览器判断时间基准是否相容
    │ 相容且未缓存
    │ GET /api/v1/captures/{capture_id}/samples
    ▼
解码 little-endian uint16 → 保留完整原始帧
    │
    ├─ 原始模式：截取连续窗口
    └─ 归一化模式：完整帧 min-max → 截取连续窗口
    ▼
统一坐标变换后逐样本绘制到 Canvas
```

现有单条样本接口保持不变，继续返回原始 little-endian `uint16` 字节。浏览器按选择顺序逐条加载；不增加 `/samples/batch`，也不把多个样本 BLOB 包装成 JSON。

### 9.2 实时波形数据流

周期、Sweep 或单次采集响应提供 `last_capture_id`/`capture_id` 后，浏览器不得使用页面当前配置推断该帧的采样属性。实时帧按以下顺序加载：

```text
会话或单次响应中的 capture ID
    │ GET /api/v1/captures/{capture_id}
    ▼
取得该帧实际元数据和 storage 状态
    │ 检查 followLatest、viewRevision 和相容性
    │ GET /api/v1/captures/{capture_id}/samples
    ▼
再次确认当前查看状态和选择状态
    ▼
加入当前波形组并绘制
```

该规则同样适用于 Sweep，不能以当前 DRAFT/APPLIED 配置代替具体帧的实际配置。`SAVE_NONE` 临时帧被下一帧替换、导致详情或样本请求返回 404 时，页面跳过该帧并等待下一个正常刷新，不把它当作采集失败，也不停止会话轮询。

`GET /api/v1/captures/{capture_id}` 的详情响应必须在所有分支统一包含 `storage`：

- 未归档且不保留的临时帧返回 `TRANSIENT`；
- `SAVE_LAST` 会话运行中的滚动帧返回 `ROLLING_LATEST`；
- 已进入 `captures` 归档表的帧返回 `ARCHIVE`。

当前归档分支需要补充 `storage: "ARCHIVE"`，但不改变任何数据库记录或保存决策。前端只能依据详情接口的实际响应更新保存标签，不能仅因会话进入终态就自行推断为 `ARCHIVE`。

当 `followLatest=false` 时，页面只记录新的 `latestCaptureId` 并提示有新波形，不自动发起会覆盖当前人工视图的绘图流程。恢复跟随后再按上述两步接口加载最新帧。

### 9.3 历史摘要增量

`GET /api/v1/captures` 的每个 item 在现有字段基础上增加：

```json
{
  "sample_interval_ticks": 120,
  "pretrigger_count": 64
}
```

`sample_count` 已存在。三个字段均来自现有 `captures` 表列，只扩展 SELECT、`CaptureSummary` 和 JSON 输出，不修改数据库表结构。新增字段是向后兼容的 REST 响应扩展，现有 CLI 可以忽略它们。

### 9.4 只读存储信息接口

新增：

```http
GET /api/v1/storage
```

建议响应：

```json
{
  "backend": "sqlite",
  "runtime_database_path": "/var/lib/usac/database/acquisition.sqlite3",
  "host_database_path": "/var/lib/tuss4470/core/acquisition.sqlite3",
  "path_mapping": "bind_mount"
}
```

字段规则：

- `runtime_database_path` 来自 `CaptureStore.path` 的绝对路径，是 core 进程实际打开的文件；
- `host_database_path` 是部署时传入的只读展示值；裸机运行未单独传入时，与 runtime 路径相同；
- `path_mapping` 取 `same_as_runtime` 或 `bind_mount`；
- Windows 裸机页面通常显示 `D:\Desktop\TUSS4470_data\core\acquisition.sqlite3`；
- Jetson Docker 页面同时显示宿主持久化路径和容器内运行路径；
- Windows 和 Jetson Compose 均以现有 `USAC_CORE_DATA_DIR` 作为 bind mount `source` 与页面宿主路径的唯一配置来源，并在其后追加固定数据库文件名 `acquisition.sqlite3`；
- Compose 把由 `USAC_CORE_DATA_DIR` 得到的宿主路径作为不透明显示文本传给 core，同时继续把容器实际路径作为 `--database` 传入；容器不得把 Windows 宿主路径当作 Linux 路径解析，也不得自行反推 bind mount；
- 接口不接收请求体，不提供 POST/PUT/PATCH/DELETE 版本，也不触碰设备锁或 USB；
- 页面只提供复制按钮，复制的是用户当前选择的宿主或运行路径文本。

该接口失败不得阻止设备状态、采集、历史或波形功能；页面只在存储卡片中显示“路径暂不可用”。

## 10. 状态更新规则

- 单次采集成功后，沿用现有流程加载最近波形和历史；
- 周期/Sweep 运行时，沿用现有单槽刷新策略，只替换“最近波形”，不把每次刷新无限累积到浏览器；
- `followLatest=true` 时，新帧可以更新当前画面；`followLatest=false` 时只更新最新 ID、计数与历史，绝不覆盖人工查看画面；
- 用户手动查看或叠加历史后保持暂停跟随，直到明确点击“恢复跟随最新”；采集本身不暂停；
- 用户手动选择的历史叠加项只有在相容时保留；设备配置应用不主动清除已加载波形；
- `SAVE_LAST` 会话结束后重新读取 `last_capture_id` 元数据并刷新其 `storage` 标签，使滚动记录准确变为已归档；
- 语言切换、历史分页和存储路径刷新不得触发设备配置或采集；
- 页面刷新后不恢复之前的叠加选择，避免自动加载大量历史数据；
- 下载链接始终指向原始 `/samples` 接口，与当前窗口和归一化模式无关。

## 11. 错误处理

### 11.1 样本加载

- HTTP 失败只标记对应波形加载失败，已经显示的其他曲线不清除；
- 返回字节数为奇数时拒绝解码；
- 解码样本数与元数据 `sample_count` 不一致时拒绝加入叠加组；
- 同一波形正在加载时禁止重复发起请求；
- 用户在请求完成前取消选择时，完成结果不得重新把该波形加入画布；
- 异步加载完成后必须同时验证请求的 `viewRevision` 仍属于当前波形组，并验证记录仍被选择或仍是当前主波形；查看其他波形、清除叠加、恢复跟随或最新帧重建组之后返回的旧结果一律丢弃；
- 上述归属验证同时适用于异常和收尾路径；旧请求失败不得产生当前视图提示，旧请求的 `finally` 不得删除新视图状态或释放新请求的预留名额；
- 已不存在的临时 capture 返回 404 时，移除其页面状态并提示其未持久化。

### 11.2 窗口与归一化

- 无效窗口不触发绘图异常，不覆盖上一个有效窗口；
- 空波形不能参与绘制；
- 恒定波形按第 6.2 节处理；
- 单条波形异常不得导致整个历史列表或采集控制失效。

### 11.3 存储路径

- 接口不可用时显示局部错误；
- 路径只按文本处理，不拼接成浏览器可访问 URL；
- 复制失败时显示可手工选择的完整文本；
- 不向该接口加入密钥、令牌或其他敏感配置。

## 12. 中英文与可用性

所有新增标题、按钮、单位、错误、上限提示、相容性原因、临时数据标记和存储路径标签必须进入现有 `I18N` 字典，并随右上角语言按钮即时切换。语言选择继续使用现有浏览器本地保存方式。

输入框必须有关联标签和范围说明；图例不能只依赖颜色；按钮在加载或达到上限时使用真实 `disabled` 状态；Canvas 保留可理解的 `aria-label`，并在画布外提供当前曲线数量、窗口范围和显示模式的文字摘要。

## 13. 性能与复杂度约束

- 最多绘制 `20 × sample_count` 个真实点；当前 2048 点时为 40,960 点，原生 Canvas 足够；
- 不增加后台工作线程、前端框架或服务端图形处理；
- 不预加载整页历史波形，只加载用户选择的记录；
- 归一化结果按 capture ID 缓存，窗口移动不重复计算；
- 窗口、显示模式、图例显隐和尺寸变化只重绘，不访问网络；
- 历史分页仍保持现有有界查询；
- 页面不得因为存储路径接口或某条波形失败而停止设备状态轮询。

## 15. 测试设计

本增量按 TDD 实施，测试不访问 COM9、不刷写固件、不产生 Burst。

### 15.1 Python/API 测试

1. 历史 item 包含正确的 `sample_interval_ticks`、`pretrigger_count` 和原有 `sample_count`；
2. 历史分页、session 过滤及现有 CLI 不受新增字段影响；
3. 单帧详情对临时、滚动和归档记录分别返回 `TRANSIENT`、`ROLLING_LATEST` 和 `ARCHIVE`；
4. `SAVE_LAST` 同一个 capture ID 在会话终态前后从 `ROLLING_LATEST` 变为 `ARCHIVE`，原始样本和数据库保存语义不变；
5. `/api/v1/storage` 在 Windows/裸机模型下返回相同的 host/runtime 路径；
6. Docker 模型下返回不同但明确的 host/runtime 路径及 `bind_mount`；
7. 存储信息查询不访问设备客户端，不受设备断开或执行器忙状态影响；

### 15.2 Node 前端行为测试

1. little-endian 原始样本完整解码，无抽点；
2. 起点、点数、上一窗口、下一窗口和显示全部的边界正确，单点窗口能画出一个点且没有除零；
3. 归一化使用完整帧 min/max，而不是当前窗口；
4. 原始纵轴保留实际 ADC 刻度，归一化纵轴固定为 `0..1`，恒定帧归一化全部为 0；
5. 原始/归一化切换不重新请求样本；
6. 相容三字段全部一致时允许叠加，任一不同时拒绝并报告字段；
7. 主波形、隐藏曲线和加载中预留项按不同 capture ID 合计最多 20 条，隐藏不释放名额，移除后可以继续选择；
8. A 加载期间查看 B、清除叠加或恢复跟随后，A 的迟到成功、失败和 `finally` 收尾均因 `viewRevision` 或请求身份不符而被隔离，不能覆盖 B、误报错误或释放 B 的名额；
9. 单条下载失败、长度错误和快速取消不会破坏其他曲线；
10. 查看或叠加历史会暂停 `followLatest`，新帧不覆盖人工视图；恢复跟随后加载最新帧，但采集与会话轮询始终继续；
11. 实时波形先从单帧详情接口取得该帧实际元数据，再加载样本；测试证明 Sweep 不使用页面当前配置代替帧元数据；
12. 临时帧被替换后返回 404 时跳过该帧并继续轮询；
13. `SAVE_LAST` 终态对同一 capture ID 重新读取详情，并且只有详情实际返回 `ARCHIVE` 时才将缓存标签从滚动记录更新为已归档，不重复下载样本；
14. 应用新配置不会主动清除已加载历史波形，只有实际新帧不相容时才重建组；
15. 存储路径接口失败不停止设备状态轮询；
16. 新增文案均可中英文切换；
17. 下载仍指向完整原始样本，不受窗口或归一化状态影响。

## 16. 验收标准

本增量只有同时满足以下条件才可关闭：

- 页面主要波形区域位于纵向布局中央并可随页面宽度调整；
- 用户可精确显示任意合法连续原始窗口；
- 横轴明确表示原始样本序号，单点窗口可见；原始纵轴显示实际 ADC 刻度，归一化纵轴固定为 `0..1`；
- 绘图使用窗口内每一个真实样本，没有插值、降采样或伪造数据；
- 原始 ADC 和整帧独立归一化模式切换正确；
- 主波形、隐藏曲线和加载中记录合计最多选择 20 个不同 capture ID，并能识别不相容时间基准；
- 人工查看历史时暂停画面跟随且不暂停采集，恢复跟随入口明确；任何旧异步请求都不能进入已经切换的波形组；
- 本版为静态历史叠加，不把实时曲线持续混入人工叠加组；
- 实时帧使用自己的单帧元数据进行判断，详情统一返回 `TRANSIENT`、`ROLLING_LATEST` 或 `ARCHIVE`；`SAVE_NONE` 404 可跳过，`SAVE_LAST` 只有在同一 ID 的详情实际返回 `ARCHIVE` 后才更新归档标签；
- 历史叠加复用现有单条样本接口，没有新增批量接口；
- SQLite 原始数据、schema、下载内容和保存策略没有变化；
- Windows 与 Jetson 页面均能明确显示正确的数据库宿主路径；Docker 场景同时显示容器运行路径，展示值与挂载 source 由同一个 `USAC_CORE_DATA_DIR` 配置派生；
- 页面不能修改数据库位置；
- 所有新增界面和提示均支持中文/英文；
- 全部新增测试与既有离线回归通过；
- 代码审查确认没有固件、硬件控制、串行协议或采集事务逻辑变化。

## 17. 后续可扩展点

以下能力可以建立在本设计的数据缓存和绘图边界上，但不在本次实现中：

- 手动或自动波形对齐；
- 公共参考波形与相关性比较；
- 峰值、TOF、窗口能量和频域特征覆盖层；
- 实验标签和批量导出；
- 用户选择的固定 ADC 纵轴范围；
- 超过 20 条的大规模离线分析工具。

这些扩展必须继续以原始样本为事实来源，不能把浏览器归一化或显示坐标回写为采集数据。
