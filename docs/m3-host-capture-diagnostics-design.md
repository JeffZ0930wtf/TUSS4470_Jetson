# M3 主机采集阶段诊断设计

## 文档说明

本文档规定 M3 首次真实波形采集失败后的最小主机侧诊断增强，用于回答采集事务停在回环、`CAPTURE_ONCE` ACK 还是 `CAPTURE_DATA` 传输阶段。它仅适用于 M3 Windows 首次波形验证，是总体采集模块设计和 M3 实施记录的补充；不修改设备协议、MCU 固件、硬件配置或采集参数。

## 目标与边界

在现有 `run_m3_capture` 数据流中加入可选阶段回调，由 CLI 将事件即时输出到标准错误流。库调用方未提供回调时行为保持不变。

本次只记录：

- 固定配置及回环已经通过；
- `CAPTURE_ONCE` 已发送；
- ACK 已收到并通过校验；
- `CAPTURE_DATA` 帧头已收到及其声明长度；
- CAPTURE_DATA 累计接收字节数；
- 数据校验和文件保存完成；
- 异常发生时的最后阶段和累计接收字节数。

本次明确不做：

- 新增或修改协议消息；
- 修改固件、定时器、ADC、DMA、USB 或 TUSS4470 控制；
- 自动重试或发送第二次 `CAPTURE_ONCE`；
- 新增诊断服务、数据库表、日志框架或长期日志文件；
- 将诊断输出混入 CLI 成功结果 JSON。

## 接口与输出

`run_m3_capture` 增加一个可空的阶段回调参数。事件使用少量稳定字段表达：阶段名、已接收字节数，以及仅在已知时提供的期望字节数。回调只观察状态，不控制采集流程。

CLI 在标准错误流逐行即时输出诊断事件，标准输出仍只保留成功结果 JSON。发生异常时，错误文本附带最后阶段和接收进度，随后按现有逻辑拉低 DTR 并关闭串口；不重发任何命令。

## 数据流

1. 现有 HELLO、配置回读/重写和安全回环保持不变。
2. 回环通过后报告阶段事件。
3. 写出唯一一次 `CAPTURE_ONCE` 后立即报告事件。
4. ACK 完整接收并校验后报告事件。
5. CAPTURE_DATA 读取函数在取得帧头后报告声明长度，并在每次获得非空串口数据后报告累计字节数。
6. 完整帧通过协议校验并写入三个证据文件后报告完成事件。
7. 任一步异常均保留原异常类型，并补充最后阶段和字节进度。

## 测试与验收

使用现有模拟串口覆盖三种情况：

- ACK 前超时：显示 `CAPTURE_ONCE` 已发送，但没有 ACK；
- ACK 成功、CAPTURE_DATA 部分接收后超时：显示准确累计字节数；
- 完整成功：阶段顺序正确，2048 点原始数据及三个证据文件与原行为一致。

完整离线测试必须继续通过。诊断补丁本身不授权再次上电采集；下一次真实 Burst 仍需单独确认。

## 诊断结论与后续设计

该诊断在真实硬件上确认设备已经返回 `CAPTURE_ONCE` ACK 和合法的 4324 字节
`CAPTURE_DATA` 帧头，故障发生在设备发送完整帧期间。主机改为有界读取并按
接收进度刷新静默超时后，第二次采集仍在帧头后的两个 64 字节片段处停止，
因此固定总时限不是根因。

后续设备发送修正及产品化扩展边界由
`docs/m3-capture-transport-design.md` 规定。本文档继续作为观察性诊断设计，
不得被解释为授权自动重试、增加 Burst 或改变采集参数。
